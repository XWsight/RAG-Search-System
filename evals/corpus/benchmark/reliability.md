# 幂等、任务与供应商可靠性

## 幂等创建

创建请求使用租户、操作名和 Idempotency-Key 形成唯一窗口，并绑定请求内容摘要。同一个 key 与相同请求应返回原资源；同一个 key 配不同文件必须冲突。资源和任务绑定成功前的预留不能被并发请求重复占用。

## 协作取消

运行中的 Python 工作不能被安全强杀，因此取消采用持久意图和协作检查点。先把知识库写为 `CANCELLING`，再通知 worker；worker 在解析、向量化或提交边界检查令牌。已经提交 `READY` 后到达的取消不能回滚成功结果。

## 任务历史

进程重启后不能继续执行旧 Python callable，但任务 ID、状态和有限结果快照可以持久保存。启动恢复将仍然活跃的旧任务标记为 `FAILED/worker_restarted`，再依据知识库目录状态创建新任务；旧 ID 在保留期内仍应可查询。

## 外部重试

模型与搜索请求必须设置连接和读取超时。只对连接中断、限流和服务器临时错误进行有限、带抖动的退避重试；认证失败、请求格式错误和安全拒绝不应重试。返回给客户端的错误使用稳定分类，不能透传完整上游正文。
