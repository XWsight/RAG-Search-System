# 从单节点到多节点

## 单节点边界

SQLite、本地文档目录、嵌入式 Chroma、进程内会话和线程任务池适合受控单节点部署。它们简化事务边界和故障恢复，但不能让多个容器同时写同一数据根，也不提供节点故障自动接管。

## 外部任务队列

多节点建库需要耐久任务队列、worker 租约、心跳、可见性超时、有限重试和死信处理。消息只保存稳定任务描述与资源 ID，不能尝试序列化任意 Python callable。任务处理器必须幂等，因为消息可能至少投递一次。

## 共享持久层

横向扩展时可以用 PostgreSQL 保存目录、幂等记录和任务状态，用对象存储保存原始文档，用独立向量服务保存索引。跨系统仍然没有天然 ACID，需要事务 outbox、状态机和对账任务保证最终一致。

## 无状态 API

API 副本不应保存唯一会话、限流桶或资源锁。会话与分布式限流迁移到共享存储，资源并发控制使用数据库条件更新或租约。只有 API 无状态、worker 可独立扩容后，负载均衡和滚动升级才具有可靠语义。
