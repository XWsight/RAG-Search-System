# 认证、授权与租户隔离

## 密钥处理

API Key 只在启动配置解析时短暂出现，认证器内部保存固定长度摘要，并使用恒定时间比较。异常、日志和对象表示不得包含原始密钥。请求同时携带 Bearer 与 `X-API-Key` 属于歧义输入，应统一拒绝。

## 角色权限

reader 可以查询知识库和提交问答，writer 可以创建与删除知识库，operator 才能读取运维指标。权限检查应发生在业务调用之前，并由稳定角色集合驱动，不能依赖前端隐藏按钮实现授权。

## 资源归属

每次读取、更新和删除都必须同时使用资源 ID 与认证租户 ID 查询。跨租户访问与不存在资源返回相同的安全错误，避免攻击者通过状态码或错误信息枚举其他租户的资源。

## 容量隔离

数据隔离不等于服务质量隔离。每租户任务数、会话数、上传总量和请求速率需要独立配额，同时还要保留全局上限。公平调度应防止一个合法租户占满全部 worker，使其他租户长期饥饿。
