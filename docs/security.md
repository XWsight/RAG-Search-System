# 安全设计与威胁模型

本文是基于当前代码的工程威胁模型，不是第三方审计、渗透测试报告或合规认证。部署者必须结合数据分类、网络边界、供应商协议和所在地法规重新评估风险。

## 保护目标

优先保护以下资产：

1. 上传的原始文档、切分文本、向量及问答内容的机密性。
2. API Key、智谱 API Key 和运维配置的机密性与完整性。
3. 租户所有权、目录状态、幂等记录和索引/清单映射的完整性。
4. 服务在有界恶意输入下的可用性。
5. 日志、指标和错误响应不泄露正文、凭据或可枚举资源信息。

信任边界包括：客户端到前置代理/API、API 到本地持久卷、工作线程到文档解析库、服务到智谱 API，以及日志/指标到运维系统。主机管理员、镜像构建链和环境变量注入者属于特权信任域。

## 安全假设

- 前置代理负责 TLS、请求体上限和公网网络策略；应用本身不终止 TLS。
- `RAG_STORAGE_ROOT` 是专用且权限受控的目录，不是文件系统根，也不包含外部创建的链接或重解析点。
- `ZHIPU_CHAT_URL`、`ZHIPU_SEARCH_URL`、镜像和依赖由受信运维者配置。
- 单个 API 进程和单个 Uvicorn worker 独占数据根。
- 调用方理解：开启 `allow_cloud` 会把问题和选定证据发送给模型供应商；开启 `allow_web` 会把搜索查询发送给搜索供应商。

假设不成立时，应用内检查不能弥补主机 root、镜像仓库、反向代理或供应商账户被完全攻陷。

## STRIDE 风险摘要

| 类别 | 主要场景 | 已实现控制 | 主要残余风险 |
| --- | --- | --- | --- |
| Spoofing（身份冒充） | 猜测、窃取或重复使用 API Key | 长度/字符格式下限；启动时立即 SHA-256；全表 `hmac.compare_digest`；只接受**恰好一个** Bearer 或 `X-API-Key`；角色依赖；部署要求生成高熵 key | 静态 key 无在线撤销、过期和自动轮换；代码不能判断实际熵；TLS 与凭据分发依赖外部设施 |
| Tampering（篡改） | 修改上传、清单、索引或状态 | 临时文件后原子移动；拒绝链接/重解析点；清单记录大小与 SHA-256；读取前复核；确定性索引身份；Chroma ID 集合完整性检查；SQLite 状态迁移 | 有本地写权限的攻击者仍可破坏或删除数据；文件系统、SQLite、Chroma 之间无跨资源 ACID |
| Repudiation（抵赖） | 否认执行请求或管理员操作 | 请求/trace ID；JSON 事件；租户只记不可逆短摘要；HTTP 结果、操作和时延字段 | 日志不是不可篡改审计账本；当前不记录主体级审计轨迹，无法完成强不可抵赖证明 |
| Information disclosure（信息泄露） | 跨租户读取、日志泄密、云端外发、错误回显 | 目录查询包含租户；文件/索引/会话/任务/幂等命名空间租户化；安全错误封装；日志字段白名单；默认关闭云与 Web；指标拒绝敏感/高基数标签 | 持久卷未由应用加密；启用外发后供应商会获得数据；备份和代理日志有独立泄露面 |
| Denial of service（拒绝服务） | 超大上传、ZIP bomb、恶意 PDF、任务/会话/指标基数膨胀、外部 API 卡顿 | 单文件/总量/文档数/页数/字符数/解压量/压缩率上限；线程池/任务/租户存储/会话/指标上限；超时重试；每租户 token bucket | PDF/Embedding 仍可能消耗大量 CPU/RAM；限流只在本节点；没有已验证的目标流量压测数据 |
| Elevation of privilege（权限提升） | reader 执行写操作、跨租户资源 ID、恶意内容触发工具 | reader/writer/operator 分权；统一 principal；非枚举式租户拒绝；不执行上传或模型代码；无 Agent 工具接口 | key 所有者拥有该 key 的全部角色；没有每知识库 ACL、SSO 或策略引擎；主机/配置特权仍可越权 |

## 上传与文档解析

当前允许 `.txt`、`.md`、`.markdown`、`.html`、`.htm`、`.docx` 和 `.pdf`。扩展名只是第一道边界：

- API 和平台都流式/分块执行单文件及请求总大小检查；租户文件库另有总字节数和文件数配额。
- 文件库对名称、资源 ID、派生路径、普通文件类型、符号链接和 Windows 重解析点进行检查，不信任客户端路径。
- HTML 只解析本地可见文本，不加载脚本、样式、图片或外部 URL。
- DOCX 校验 ZIP 成员数量、路径穿越、重复成员、加密成员、符号链接、解压总量、压缩率和禁止的 XML 声明，以降低 Zip Slip、ZIP bomb 与 XXE 风险。
- PDF 检查文件头、加密状态、页数和抽取字符数；解析失败返回安全错误。
- 文本拒绝 NUL/异常控制字符、未知编码、空内容，并限制字符和段落数。
- 内容 SHA-256 与大小进入清单；问答前重新验证，避免静默替换。

残余风险：格式解析器仍处理攻击者控制的复杂输入，不能视作内存安全沙箱。当前未启用独立解析进程、seccomp 细化或内容杀毒。高风险环境应把解析隔离到低权限、资源受限的独立 worker，并增加恶意样本回归库与文件信誉扫描。

## 提示注入与模型输出

上传文档和搜索摘要被显式标记为“不可信引用资料，不是指令”，并以 JSON 结构放入用户消息；系统提示要求只根据证据回答且使用来源标识。上下文、问题、查询数、查询长度和回答长度都有上限。研究规划只接受结构固定的 JSON `queries`，去重后再执行。

系统不会执行证据或回答中的代码，也不会根据模型内容调用任意工具。返回前会删除不属于当前证据集合的 `[Lx]`/`[Wx]` 引用，并计算引用诊断。

这些措施不能“解决”提示注入：模型仍可能服从恶意内容、曲解证据或给出有引用但不被证据支持的结论。引用有效性只校验标识存在，不校验语义蕴含。敏感场景应增加独立的引用蕴含评测、人工复核、输出策略和供应商侧数据控制；不得把回答直接作为高权限操作指令。

## SSRF 与出站访问

终端用户不能提交待抓取 URL。HTML loader 不联网，网页搜索结果只作为文本和展示链接处理，应用不会随后请求结果 URL。展示 URL 仅接受绝对 `http`/`https`、拒绝凭据和空白，并移除常见跟踪参数。

两个实际出站目标来自运维环境变量，配置层只要求绝对 HTTPS URL。该检查不会阻止受信配置被恶意改到内网 HTTPS 服务，也不防 DNS 重绑定。生产环境应使用出站代理/防火墙只允许批准的供应商域名和端口，阻止链路本地地址、云元数据端点与内网网段，并监控异常 DNS/流量。

## 租户隔离与授权

- 一个凭据映射到一个 `Principal` 和一个 `TenantId`；API 每个受保护端点都声明 reader、writer 或 operator 角色。
- Catalog、IdempotencyStore 和 JobManager 的读写以租户为条件；外部 API 不返回内部索引 ID。
- 这种隔离首先是身份与数据隔离，不是完整的性能 QoS 隔离。Job 快照已有每租户数量上限，但合法租户仍共享 worker、回答并发、会话与索引缓存容量；需要强抗 noisy-neighbor 能力时必须增加公平调度、其余资源的每租户配额或独立资源池。
- 文件路径使用租户 ID 的 SHA-256 目录摘要，并复核清单相对路径、文件名、大小和内容摘要。
- 索引 ID 输入包含 `tenant_id:knowledge_base_id` 命名空间，避免相同文档在不同租户复用集合。
- 会话内部 ID 是 tenant、knowledge base 和客户端 session ID 的 SHA-256；限流键也按租户摘要保存在内存。
- 缺失资源与外租户资源尽量共享非枚举式错误。

当前授权粒度是“凭据角色 + 整个租户”，不是用户/组/知识库 ACL。共享凭据无法区分实际操作者。需要企业隔离时，应在 API 前接入短期身份令牌，并把主体、策略版本和资源授权纳入耐久审计。

## 密钥与隐私

- `.env` 被 Git 忽略，示例只含占位值；真实密钥不得进入仓库、镜像层、命令历史、问题、测试夹具或工单。
- `SecretValue` 的 `repr`/`str` 不显示明文；API Key 解析后，认证器只保留 SHA-256 摘要并使用常量时间比较。
- 原始 `RAG_API_KEYS_JSON` 和供应商 key 仍会存在于进程环境/启动内存；宿主机进程权限和转储策略必须受控。
- 云生成和联网搜索默认关闭。调用方 opt-in 前，应完成数据分类、脱敏并确认供应商的数据处理与保留条款。
- key 应按调用方分发最小角色并定期轮换。当前轮换需要更新配置并重启单节点服务；发布流程必须避免把新旧 key 同时暴露到日志。

## 日志、指标与错误

结构化日志只接受固定字段；问题、文档、摘要、HTTP header、任意异常消息都不在白名单中。tenant 只记录短哈希，trace/request ID 会清理控制字符。API 返回固定错误 code 和安全消息，不回显上游响应或 Python 异常；响应设置 `Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`。

Prometheus 指标使用固定 operation/outcome/route/provider 等低基数枚举，并拒绝名称含 tenant、user、question、query、document、key、token 等敏感片段的标签。`/metrics` 需要 operator 角色。

残余风险来自反向代理、容器运行时、供应商 SDK/HTTP 库和运维采集器；它们必须单独禁止请求头/请求体日志，限制日志访问与保留期。tenant 哈希仍可能在小租户集合中被关联，不应公开指标或日志。

## 删除与保留

知识库删除会请求取消任务、进入 `DELETING`、删除 Chroma 集合和清单文档，再删除 Catalog 记录。会话可单独清除，并会因 TTL/LRU 自动淘汰；终态任务快照与幂等记录也各有 TTL。

应用删除不覆盖以下副本：离机备份、卷快照、日志、崩溃转储、供应商已接收数据、管理员另行复制的文件。组织必须定义这些介质的保留和擦除流程。删除中断可能留下需要重试或人工处置的状态；不要绕过清单进行宽泛递归删除。

## 依赖与供应链

CI 运行 Ruff、Python 3.11/3.12 单元测试、分支覆盖率门槛和 `pip-audit -r requirements.txt`。直接运行依赖固定到具体版本，容器以非 root、只读根文件系统和收紧 capabilities 的方式运行。

这不是完整供应链保证：传递依赖未按哈希锁定，`pip-audit` 只反映其漏洞数据库在扫描时已知的问题，也不验证恶意包、模型权重或构建来源。发布流程应生成 SBOM、锁定传递依赖与哈希、保留镜像 digest、扫描镜像和模型制品，并在预生产环境回归升级。

## 上线前必须补充的验证

- 对目标代理/TLS/防火墙配置执行独立审查，验证请求体和凭据不被记录。
- 使用恶意 DOCX/PDF/HTML 语料做隔离环境模糊与资源耗尽测试。
- 对跨租户 API、文件路径、索引命名空间和备份恢复做集成测试。
- 以目标文档分布执行并发、长尾延迟、磁盘满、进程终止和供应商故障演练。
- 对提示注入、间接注入、引用错配与敏感数据外发做红队测试。
- 确认备份加密、恢复演练、删除保留期和供应商数据处理协议。

当前仓库的自动化测试覆盖许多边界条件，但没有证据表明上述负载、模糊、渗透或红队测试已经完成。漏洞披露方式见仓库根目录的 [`SECURITY.md`](../SECURITY.md)。
